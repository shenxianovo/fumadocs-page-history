Both compiler plugins accept the same settings. For installation, start with [Getting started](/docs). For a walkthrough, use the guides for [workspace changes](/docs/workspace-changes), [contributors](/docs/contributors), or [display and language](/docs/localization).

## Required and optional settings

| Setting                | Required | Default                         | Meaning                                                                      |
| ---------------------- | -------- | ------------------------------- | ---------------------------------------------------------------------------- |
| `repository.url`       | Yes      | —                               | Public HTTP(S) repository URL used for commit and release links.             |
| `authorMappings`       | No       | `[]`                            | [Git identity and account associations](/docs/contributors#author-mappings). |
| `display`              | No       | Built-in defaults               | [Presentation and language controls](/docs/localization).                    |
| `github`               | No       | Disabled                        | [Build-time account lookup](/docs/contributors#optional-github-lookup).      |
| `repository.directory` | No       | Auto-discovered                 | A directory inside the local checkout, used to locate Git.                   |
| `content`              | No       | Files keep their checkout paths | Location mapping for documents copied to another directory.                  |
| `getHistoryPaths`      | No       | No extra paths                  | Additional historical paths for explicitly mapped migrations.                |
| `workspaceChanges`     | No       | `false`                         | [Inline uncommitted changes](/docs/workspace-changes).                       |

`repository.url` must have no credentials, query, or fragment. It is provided explicitly and is never inferred from remote credentials. Local paths and account-matching selectors stay in the build process.

## Per-page controls

Extend your page schema while keeping existing compiler settings:

```ts
import { pageSchema } from 'fumadocs-core/source/schema';
import { gitChangelogSchema } from 'fumadocs-page-history/schema';

const schema = pageSchema.extend(gitChangelogSchema.shape);
```

| Frontmatter                                   | Effect                                                                  |
| --------------------------------------------- | ----------------------------------------------------------------------- |
| `gitChangelog: false`                         | Disable both sections and skip Git.                                     |
| `gitChangelog: { disableChangelog: true }`    | Show contributors only.                                                 |
| `gitChangelog: { disableContributors: true }` | Show history only.                                                      |
| `authors: [alex]`                             | Add explicit contributors by mapped account, display name, or Git name. |

Explicit contributors can be credited without commits. Pages with neither commits nor explicit contributors have no footer.

## Collection options

A collection's compiler options replace global options. Register the plugin there if the collection has its own options. For MDX, retain the Fumadocs preset:

```ts
import { applyMdxPreset, defineDocs } from 'fumadocs-mdx/config';
import { remarkGitChangelog } from 'fumadocs-page-history/remark';

export const docs = defineDocs({
  docs: {
    mdxOptions: applyMdxPreset({
      remarkPlugins: [
        [
          remarkGitChangelog,
          {
            repository: { url: 'https://github.com/owner/repository' },
          },
        ],
      ],
    }),
  },
});
```

Sätteri collections register `gitChangelog(options)` in `docs.satteriOptions.mdastPlugins` and set `docs.compiler` to `'satteri'`.

## Advanced Git controls

| Setting            | Default                | Meaning                                                      |
| ------------------ | ---------------------- | ------------------------------------------------------------ |
| `filter`           | All documents          | Select absolute source paths; excluded pages skip Git.       |
| `maxGitLogCount`   | All commits            | Limit sorted results; Git still reads the full file history. |
| `excludeBots`      | `true`                 | Exclude bots from contributors, retaining their commits.     |
| `getCommitURL`     | Repository commit URL  | Customize commit links for another Git host.                 |
| `getReleaseTagURL` | Repository release URL | Customize release tag links.                                 |

History follows Git-detected renames, preserves creation commits on merged branches, includes merge changes relative to the first parent, and sorts by author date. Copies of another page start their own history. Lightweight and annotated tags are supported. Commit Markdown links `#123` to `/issues/123`; raw HTML is disabled.

### Migration history

Git can miss a rename when a migration changes most of a document, for example when converting Vue Markdown into React MDX. Explicitly list the previous paths instead of lowering rename detection thresholds for every page:

```ts
const previousPaths: Record<string, readonly string[]> = {
  'docs/about/introduction.mdx': ['docs/about/introduction.md'],
};

const options = {
  repository: { url: 'https://github.com/owner/repository' },
  getHistoryPaths: (sourcePath: string) => previousPaths[sourcePath] ?? [],
};
```

Pass these options to `remarkGitChangelog`, Sätteri's `gitChangelog`, or the Node API:

```ts
import { createHistoryReader } from 'fumadocs-page-history/git';

const reader = createHistoryReader(options);
const commits = await reader.read('docs/about/introduction.mdx');
```

`getHistoryPaths` receives the normalized repository-relative current path, including any `content` location mapping. It returns additional paths relative to the Git root, even when `repository.directory` points at a subdirectory. The current path is always included; return `[]` for pages without a migration. Every path must remain inside the repository. No `.md`/`.mdx` relationship is inferred.

Each path follows actual renames. The combined history is deduplicated by full SHA, sorted by author date (SHA breaks ties), and then limited by `maxGitLogCount`. Author mappings, co-authors, GitHub lookup, release tags, and link callbacks work on the combined result. Like other build settings, this callback and the paths themselves are not serialized into compiled pages.

### Copied documents

When compilation uses a copy of your documents, declare where it belongs in the checkout:

```ts
{
  repository: {
    url: 'https://github.com/owner/repository',
    directory: '/workspace/repository',
  },
  content: {
    directory: '/workspace/document-copy',
    pathInRepository: 'apps/docs/content',
  },
}
```

A copied `guide.mdx` reads history for `apps/docs/content/guide.mdx`. The package resolves native Windows or POSIX disk paths, handles symlinked directories, and produces Git-relative paths internally. Files outside `content.directory` and repository paths that escape the checkout are rejected. Use `pathInRepository: '.'` when the content directory represents the repository root.
