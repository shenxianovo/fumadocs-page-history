Page History brings Git context into your Fumadocs pages:

- **Page history:** a collapsible commit timeline after each document.
- **Contributors:** authors and co-authors, with optional GitHub profiles and avatars.
- **Workspace changes:** opt-in red and green highlights for uncommitted edits during local development.

[Try the interactive demo](/docs/demo) to see all three. The steps below install history and contributors. Add [workspace changes](/docs/workspace-changes) afterward if you want to review edits in the page.

## Setup

Use Node.js 24.14 or later, Fumadocs 16.17 or later, and Git with a complete checkout. Your document files normally stay inside that checkout; the plugin discovers the repository and file paths automatically.

<Steps>
<Step>

### Install the package

```npm
npm i fumadocs-page-history
```

</Step>
<Step>

### Import the styles

Import after your Fumadocs styles:

```css title="app/global.css"
@import 'fumadocs-page-history/css/preset.css';
```

</Step>
<Step>

### Register the plugin

Only `repository.url` is required:

<Tabs items={["MDX", "Sätteri"]}>
<Tab>

```ts title="source.config.ts"
import { defineConfig } from 'fumadocs-mdx/config';
import { remarkGitChangelog } from 'fumadocs-page-history/remark';

export default defineConfig({
  mdxOptions: {
    remarkPlugins: [
      [
        remarkGitChangelog,
        {
          repository: { url: 'https://github.com/owner/repository' },
        },
      ],
    ],
  },
});
```

</Tab>
<Tab>

```ts title="source.config.ts"
import { defineConfig } from 'fumadocs-mdx/config';
import { gitChangelog } from 'fumadocs-page-history/satteri';

export default defineConfig({
  compiler: 'satteri',
  satteriOptions: {
    mdastPlugins: [
      gitChangelog({
        repository: { url: 'https://github.com/owner/repository' },
      }),
    ],
  },
});
```

</Tab>
</Tabs>

Contributors and history appear after each committed document. No page-template changes are needed.

</Step>
</Steps>

Keep your existing plugins. If a collection has its own compiler options, register Page History there using the [collection configuration](/docs/configuration#collection-options). Sites with blog posts or other MDX collections should register it only for the intended collection.

## Check the result

- History is read during compilation; Git is not needed in the deployed site.
- File renames, co-authors, and release tags are included.
- Both sections are enabled; the history timeline starts collapsed.
- Dates switch from UTC server HTML to the reader's browser time zone after hydration.
- New pages without commits or explicit contributors have no footer. Development logs explain why.
- History and contributor records are compiled into the page. After a Git-only change, restart the development server or build again. The optional workspace comparison refreshes automatically; it has a separate lifecycle.

## Build and deploy

Git and the full repository history must be available during compilation. The deployed site does not need Git for the history footer. GitHub Actions needs a full checkout:

```yaml
- uses: actions/checkout@v6
  with:
    fetch-depth: 0
```

For an existing shallow clone, run `git fetch --unshallow`.
